## One project, two lenses: Builder and Engineer

Build and Engineer are no longer two modes. They are two **lenses** on the same project. The switch in the title bar now reads **Builder ⇄ Engineer**, and flipping it changes only what you see. Your sessions, files, preview and setup stay as they are. A project started in the Builder lens opens in the Engineer lens with its terminals, diffs and language server, and an engineer's project opens in the Builder lens with its preview, saved versions and plain-language summaries. Your earlier choice, per project and from onboarding, carries over unchanged.

The Builder lens has a new strip above the chat with three tools:

- **What changed: "Go back to when it worked".** Each saved version and each finished agent step gets a short title and one or two plain sentences about what someone using the app would notice. It is also labelled with the part of the app it touched (data, logic, view, sign-in, going live, connected services) and how risky it was. "Go back to here" restores a version by that title, through Build. Your connected agent writes each summary once in the background with the cheaper model, and Canopy saves it, so reopening the project costs nothing.
- **Something's wrong.** Describe the problem and Canopy runs a **diagnose-only** check. The agent reads the project, the preview's console and network errors, and the recent changes, then tells you the likely cause, the evidence, a suggested fix and how confident it is. This check is read-only by construction, so it never changes your project. Tick **Get a second opinion** to run two diagnoses in parallel, each starting from a different angle, and see whether they agree. Nothing is fixed until you click **Fix it**. Build then makes the fix with the diagnosis attached. After **three** fixes for the same problem fail, Canopy stops offering a fourth. It offers **Restart from plan** instead, which goes back to the last version that worked and rebuilds from your plan.
- **How it's built.** A simple **Data / Logic / View** map of your project, written in plain words. Click a layer to see its files. Engineers can claim a layer ("I own sign-in & accounts"). When a Builder-lens change touches files in a layer someone else owns, you see "Sign-in & accounts is owned by Sam. Your change will be sent for their approval." One click sends the request to team chat. The file patterns for each layer are guessed once by your agent, and you can edit them.

If a Builder-lens project is connected to a shared online repository, a notice recommends turning on team rules, with a link to the rules editor once it is available. It is a recommendation and blocks nothing.

**When the agent is asked:** once per saved version or step for summaries (background), once per project for the layer map (background, or when you click Refresh), and each time you click "Find the cause" (one call, or two with a second opinion). If no agent is connected, you are signed out or you are over budget, the summaries fall back to what you asked for and the tools say why in one line.

**Turn it off:** Settings → Agents → **Builder lens summaries** stops the automatic summaries and the automatic layer map. Diagnoses only run when you ask.
