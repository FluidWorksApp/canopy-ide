Canopy 0.5.3 makes the companion answer Slack messages even when it has stopped, brings each new release to cloud workspaces automatically, and offers to update a workspace instead of showing an error.

### Slack messages wake the companion
A message to your companion on Slack used to get "I couldn't reach Jarvis: The companion is not running in Canopy right now" whenever the companion wasn't already running. That happened while it was still starting, after its agent stopped, or after Canopy gave up retrying, even though Canopy itself was open. The person on Slack can't see the companion or press Retry, so now their message starts it again and is answered once it's ready. Waiting for the start takes up to a minute and a half.

When the companion really can't answer, the reply now says why: it is turned off in Canopy, this computer has no agent CLI to run it on, or it couldn't start, followed by the error.

### Workspaces get each new release
A new Canopy release now reaches cloud workspaces on its own. A workspace that starts or wakes from hibernation runs the latest workspace software, so features such as branch sync no longer wait on a manual update.

### Update workspace
When a running workspace is behind, Canopy now says so with **Update available**, or **Update needed** when something in this version depends on it, instead of "This workspace is running an older Canopy host". The workspace owner can choose **Update workspace**:
- It shows each step while it works.
- It restarts the terminals and agents in that workspace.
- It keeps your files and projects.
- If the new version doesn't start, the workspace goes back to the one it was running.

If other people are connected, Canopy says how many before you confirm. Members see "Ask the workspace owner to update it."

A workspace can use **Update workspace** after it has started once on 0.5.3. Until then, hibernate and resume it to bring it up to date.
