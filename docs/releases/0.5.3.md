Canopy 0.5.3 makes the companion answer Slack messages even when it has stopped.

### Slack messages wake the companion
A message to your companion on Slack used to get "I couldn't reach Jarvis: The companion is not running in Canopy right now" whenever the companion wasn't already running. That happened while it was still starting, after its agent stopped, or after Canopy gave up retrying, even though Canopy itself was open. The person on Slack can't see the companion or press Retry, so now their message starts it again and is answered once it's ready. Waiting for the start takes up to a minute and a half.

When the companion really can't answer, the reply now says why: it is turned off in Canopy, this computer has no agent CLI to run it on, or it couldn't start, followed by the error.
