Canopy 0.4.9 makes shared cloud workspaces lighter for teammates, recovers terminals that were stuck reconnecting, and records what went wrong when a remote terminal or desktop doesn't show up.

### Teammates in a shared workspace
Each request a teammate made to a shared workspace used to re-check their runtime from scratch, starting a short-lived helper container every time. With one teammate connected, a workspace could start about 100 of these a minute. Teammates now reuse a check made in the last 2 seconds, and the helper runs only when a runtime starts. In our tests, a teammate's typical request went from about half a second to under a millisecond, and opening a terminal from about 1.7 seconds to a quarter of a second.

### Terminals stuck reconnecting
A remote terminal whose session no longer exists now ends with a message instead of reconnecting forever. A workspace stuck on "Reconnecting" or "Sign in" can now recover from Retry without restarting Canopy.

### Faster reconnects
A remote terminal that lost its connection used to wait out a backoff of up to 30 seconds, even once the workspace was answering again. It now reconnects as soon as the workspace answers. When Canopy's window freezes and the reload doesn't fix it, because the new window freezes again straight away, Canopy now waits for the window to recover instead of reloading it twice more and dropping every remote terminal each time.

### Diagnosing remote terminals and the desktop
When a remote terminal or desktop stays blank, there is now a record of it. Canopy notes terminal attach failures, stream retries, the first terminal output, and desktop connects and disconnects in its resilience log, without any terminal contents, paths or tokens. The workspace host logs when it refuses or loses a terminal or desktop connection.

### Messages and jobs to cloud workspaces and teammates
An agent messaging a cloud workspace's agent, or sending a job to a teammate, was often told "Canopy didn't answer in time … try again" while the send was still on its way. Retrying could deliver it twice. Sends now get enough time to finish. If one still doesn't confirm, the agent is told the outcome is unknown and given an id to retry with, and the same id is never delivered twice. Messaging a cloud workspace's agent by its terminal id works again, and replies stay threaded.

### Workspace image builds
Workspace image builds work again after the Cursor CLI installer changed upstream.

The shared-workspace and host logging changes need your workspace's latest host software, installed separately.
