Canopy 0.5.0 gives Canopy a brain: connect the agent CLI you're already signed in to, and it checks your agents' work against real evidence, plans before they start, reviews what was asked instead of raw diffs, tells agents about each other's changes, remembers team decisions, enforces team rules, and shows what agent work costs and achieves.

### Connect your brain
The first thing Canopy now asks is to **Connect your brain**. It finds the agent CLIs on this computer, such as Claude Code, recommends one, and checks it straight away. If the CLI is signed out, **Sign in** opens its own sign-in in a terminal; if none is installed, Canopy offers to install one. You can pick a main model and a cheaper background model, or press **Skip**: files, terminals and git never need a brain.

Canopy's own background brain work uses your plan on the cheaper model. The brain chip in the status bar shows whether the brain is connected; click it to see what each feature spent today. There, or in Settings → Agents → Brain, you can set a daily budget or a budget for one feature (0 stops it). A feature that reaches its budget stops for the day.

**Suggest message** in the commit box writes a commit message from your staged changes, only when you press it. Agents that don't name their task get a short tab title, and sessions in Agents show a one-line summary of what they're for. A name you typed always wins. Turn this off in Settings → Agents → Automatic brain work → Let the brain name sessions.

### Proof receipts
An agent saying "fixed, all tests pass" is a claim, and Canopy now checks it. When an agent finishes a turn that changed files, Canopy runs the project's own tests, typecheck and lint itself, then the brain compares your request with that evidence. The agent's status shows a receipt: **Proven**, **Partial**, **Unproven**, **Tests changed**, **Verifying** or **Unverified**.

Click it to see what you asked against what the change does, the agent's own words kept apart from what was verified, every check and its output, any test the agent weakened or deleted, and any new package that doesn't exist on npm, crates.io or PyPI. A failing check, a run with no tests, a changed test or an unknown package means the receipt can never read Proven. Without a brain, passing checks reach Partial at most.

From a receipt you can **Re-verify**, **Copy receipt**, **Share…** to team chat, or **Tell the agent** what failed. **Raise PR** now adds the latest receipt to the pull request, and **Set check commands…** chooses which commands prove a project. Choose when receipts run in Settings → Agents → Proof receipts: After every turn, When I ask, or Off.

### Plans before agents start
When you hand work to an agent through Canopy (**Run as task**, an "Ask an agent…" box, a one-off task or a ticket's **Start work**), the brain first writes a one-screen plan: the goal, the decisions the agent would otherwise guess with a recommendation for each, what it expects to touch, what counts as done, and what it won't do.

Small, low-risk work starts right away, and **Show plan** opens the plan. Riskier work waits for you, including large changes and anything touching sign-in, data, migrations, billing, CI or build config. Answer the decisions, edit the checks, and press **Approve & start**, or **Start without a plan**. If the agent later hits a choice the plan didn't cover, it's told to ask you.

**Share plan to team** posts the plan to team chat, where any teammate in the conversation can press **Approve plan…** or **Ask for changes…**. An approval starts the waiting agent on your machine, as long as your Canopy is still waiting on it. Turn planning off in Settings → Agents → Plan before an agent starts.

### Review what was asked and proven
An agent's tab and a pull request's tab now open on **Intent & evidence**: the plan, the brain's summary of how the change differs from it, the proof receipt, and the changed files riskiest first, with sign-in, data, migrations and money always at the top.

If a change is too big to review in one go, **Ask the agent to split this** sends it a suggested split. It also shows this kind of work's track record in the repository, such as "12 proven, 0 reverted", and may suggest auto-merge. That's only a recommendation: Canopy never merges anything by itself. In Settings → Agents → Intent & evidence review you can untick automatic summaries to get a **Summarize against the plan** button instead, and set the largest change to review at once (400 lines by default).

### Agents know about each other's changes
When an agent finishes a change, Canopy finds your other running agents it could affect. The brain writes each one a short note on what changed and why it matters in its terminal, and you're notified too.

When two agents touch a file nearly every change passes through, like a route table or config, within half an hour, Canopy reserves it for the one that just edited it and warns both. The new **board** view on the Agents page shows every running agent, what it's doing, its files, its latest receipt and the last note it got.

This works for agents whose CLI reports its edits to Canopy, on your computer and in cloud workspaces, including agents in your own or a teammate's cloud workspace on the same repository. Turn it off in Settings → Agents → Tell agents about each other's changes, or with the switch on the board.

### Session documents and hand-offs
Press **Open as document** in an agent's tab, or **Document** in Agents → Past sessions, to read a session as a document: the brain's summary of what it set out to do and where it stands, each turn with its files and receipt, the decisions made and why, open questions, and how much of its work is still in the code.

**Hand off…** turns the session into a packet you can read and edit, then **Copy as markdown**, **Send to a teammate** (they press **Take over** to start their own agent from it), or **Continue in a new agent**. Session documents stay private until you choose where a packet goes, and Canopy warns you if one looks like it contains a password or token.

Settings → Agents → Session documents has **Write a summary when a session document opens** (on by default) and **Add Agent-Session trailers to commits** (off by default).

### Builder and engineer are now lenses on one project
Build and Engineer are no longer separate modes. The **Builder ⇄ Engineer** switch in the title bar changes only what you see: sessions, files, preview and setup stay put, so a builder's project opens for an engineer with its terminals and diffs, and the other way round.

The Builder lens has three new tools above the chat. **What changed** describes each saved version in plain words, with **Go back to here**. **Something's wrong** finds the likely cause of a problem without changing anything, and only fixes it when you press **Fix it**; after three failed fixes it offers to restart from your plan. **How it's built** maps your project into Data, Logic and View, and engineers can claim a part so changes touching it need their approval. Turn off the automatic summaries and map in Settings → Agents → Builder lens summaries.

### Team rules that are enforced
In Agent instructions → Rules & gates, write a rule in plain words, like "Never touch the migrations folder". The brain proposes a check, shown as a sentence you can edit, and nothing is enforced until you press **Approve gate**. When a rule stops an agent, a card over its terminal says why, with **Allow once** and **Edit rule**.

Some actions always ask you, rule or no rule, such as dropping database data, force-pushing main, production deploys and moving money. **Approve once** lets that exact command run. Canopy can also keep secrets and outbound writes away from a session that has read web pages: it warns by default, and you can switch it to Block in the Rules panel.

Rules are enforced in Claude Code, on your computer and in cloud workspaces. Other agent CLIs get them as guidance. Pause or delete a rule, or switch it to Guidance, to stop enforcing it. The check on actions that can't be undone is always on.

### Team memory
The new **Team memory** icon in the left rail holds the decisions, conventions and facts your agents should know, each with who recorded it, where it came from, who it applies to and when it expires. After agents work, the brain may suggest a few things worth remembering, and you **Approve**, **Edit** or **Reject** each. Agents only see approved entries that haven't expired.

Suggestions from a session that read outside content, such as a web page, are marked Quarantined and need **Approve anyway**. When a suggestion contradicts an approved entry, both say so. Turn off suggestions or change how long entries are trusted in Settings → Agents → Team memory.

### Spend, budgets and outcomes
Each agent tab now has a budget button next to its cost, or you can write "Budget $5" in a prompt. At 80% Canopy tells you; at 100% it pauses the agent and asks you to raise the budget, and nothing is lost. Sessions in Build projects stop at $10 by default.

The new **Outcomes** panel (chart icon in the side rail) shows what agent work in this repository cost and achieved: spend, cost per merged change, receipts proven, work reverted or reworked within a week, time in review, and what the brain itself cost, with a weekly insight from the brain. Everything is counted on your computer, and the brain only sees totals.

Settings → Agents has **Session budget**, **Prototype session cap**, **At the budget** (turn off Pause the agent for warnings only) and **Spend & outcomes** (turn off Let the brain write a weekly insight).

### Sharing without links or codes
Signed in to your Canopy account, you're already connected to your teams: channels, direct messages and who's around appear on their own, end-to-end encrypted, with no code or link to exchange.

Every workspace, shared session and team message also has a readable link, such as `canopyide.dev/platform/api-server`. Open one from chat, SpotSearch (⌘K) or `canopy <link>` in a terminal. Canopy checks access every time it's opened, and message links never carry the message itself.

### Workspace credit
Canopy now warns you, by email and in Canopy, when your workspace balance drops below $5, when it reaches $0, and a final time at −$5.

At −$10, your running workspaces pause and can't start until credit is added. Your files, snapshots, settings and account are kept. Adding funds isn't available during the preview: choose **Request more credit** in Settings → Account, and the Canopy team will follow up by email.

### Cloud workspaces
GitHub pull requests and issues, worktrees, branch sync, tasks, workflows, research, undoing a turn, tracking which agent changed which file, language servers, MCP servers and search now all work in cloud workspaces. An out-of-date workspace now tells you to restart or update it instead of showing an error.

Agent awareness, team memory, proof receipts, Rules, Outcomes and per-terminal memory budgets work there too, and research can replace a write-up and import large files. Each time you connect, Canopy sends the workspace your approved rules and team memory, and offers **Update agent hooks** when its agent hooks are out of date. Shared-account sessions now show up in turns, provenance and search, and an APK built in a workspace runs on a device plugged into your computer. These need your workspace's latest image.
