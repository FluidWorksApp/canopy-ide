Canopy 0.4.7 makes remote workspaces open quickly and keep their tab names, lets agents answer the companion — including back into Slack — and lets your cloud workspace answer Slack while your desktop is closed.

### Faster remote workspaces
Switching to a cloud workspace no longer shows an empty project for up to a minute while it reconnects. Your open tabs appear straight away with their names, each marked "Reconnecting…" until its terminal is back, and they reconnect in parallel. Pick up where you left off now lists only sessions that have actually ended; sessions still running in the workspace are never offered for Resume or Reopen.

### Tab names that stay put
A name you give a tab is never changed by anything but you, across reconnects, workspace restarts, switching workspaces and restarting Canopy. Tabs you haven't named keep the name of their first request instead of turning into whatever you typed last.

### Agents can answer the companion
When the companion hands a request to an agent, the agent can now reply to it directly, and the companion receives the answer as that agent's report. A request that came from Slack gets one complete answer in its Slack thread once the agent replies; if no answer comes back in time, the companion says so.

### Slack from your cloud workspace
Settings → Companion → Slack has a new switch: Answer Slack from my workspace when my desktop is offline. With it on, your cloud workspace answers your Slack messages to the companion while no desktop is signed in, using the same agent and conversation rules as the desktop; your desktop always answers first when it is online. It answers only, never changes anything, and does not wake a workspace that is asleep. Your workspace needs the latest host software, installed separately.

### Settings
The Slack settings are now their own section, laid out like the other integrations, and show only the actions that apply: Add to Slack, Link my Slack or Unlink. Companion help text uses the same size and colour as the rest of Settings.
