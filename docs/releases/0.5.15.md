Canopy 0.5.15 adds terminals that keep running when you quit or update, a way to open another of your machines' terminals over Tailscale, previews that run in a real Chrome so logins stick, more on the agent card, and file downloads from remote workspaces.

### Persistent terminals
- Terminals, and the agents running in them, can now stay alive when you quit Canopy. The next launch reconnects them with their history, and the tabs show "Reconnecting" while they come back. They keep running for 2 hours after you quit.
- This is on by default on Mac and Linux. Turn it off with **Keep terminals running after quit** in Settings → Terminal; the change applies after you restart Canopy. Not available on Windows.
- Quit only detaches. The new Quit and Stop All… item in the app menu (Option-Cmd-Q on Mac, Ctrl-Shift-Q on Windows and Linux) stops every terminal.
- When agents are running, Stop All asks first: "Stop N running agents?", with the number of agents and shells. With persistent terminals on, you can choose Quit only instead. The dialog also counts terminals left over from an earlier launch.
- Agents that were reconnected keep their Canopy tools. They no longer point at the old launch.
- The terminal helper now ships inside the app and runs from its own copy in your home folder, so an app update does not pull it out from under running terminals.
- If a terminal cannot be reconnected, a short notice says so. If the helper cannot run, Canopy tells you once that terminals will end on Quit.

### Tailscale
- Settings → Remote access has a Tailscale row. It uses the Tailscale app already on your computer and never signs you in. It shows whether Tailscale is missing, off, waiting for sign-in or approval, or running, with a button to open the app.
- When Tailscale is running, the row lists your online machines. **Connect** shows that machine's terminals, and **Open** puts one in a normal tab, marked with a link and the machine's name. If the link drops the tab says "Reconnecting", and after 5 minutes it offers Reconnect.
- **Allow** is per machine and off by default. A machine you allow can read and type into every terminal on this computer, so only allow your own machines. It works while Canopy is open here.
- To connect from one computer to another, Allow has to be on, on the second computer, for the first.

### Previews
- Preview tabs now run in a real Chrome, one profile per project, so logins and cookies stay. Your clicks and typing go to the page; an agent that is driving waits a moment after you stop.
- Popups open in the same pane, dialogs answer inline, and file inputs use the normal file dialog.
- If you have no Chrome, Edge, Chromium or Brave, the preview offers to download Chrome Headless Shell (about 100 to 120 MB). It downloads only when you click, and Canopy checks it against a pinned checksum first.
- Without Node, or for a page Chrome cannot open, the preview uses the built-in view and says why, with Retry.
- In Settings → Browser & Vault you can switch between Chrome and the built-in view, and sign out of preview sites.
- Hovering a preview tab shows a picture of the page instead of an empty frame. Tabs that have not been in front yet show a globe and the address.

### Agent card
- Raise PR and Commit & raise PR draft the title, commit message and description with your default CLI. The title fills in only if you have not typed one.
- A pull request the agent raised itself, for example from another branch, now shows on the card instead of "Commit & raise PR". This works for new pull requests only.
- The pull request number on the card opens the pull request on GitHub.
- The card names the checks that have not passed yet, as running, queued or failed.
- If GitHub will not merge yet because of branch rules, you get Merge when checks pass instead of only an error.
- The task list stays open when you switch tabs, and the headline reads "N done · N in progress · N not started".

### Remote workspaces
- Right-click a file or folder in a remote workspace and choose Download… to save it to a folder on this computer, with progress and Cancel like Upload.
- Updating a remote workspace now waits while an agent is running in it, instead of stopping the agent. An open shell does not hold it up. The update lands the next time the workspace stops and starts.
- In All workspaces, a remote tab you closed stays closed.

### Files and workspaces
- Importing into research no longer refuses a file outside the project. Any file you have open can be imported, for example an agent's draft in its scratch folder.
- When an agent opens a file or a diff outside every open project, Canopy follows Settings → Privacy → Files outside projects instead of always refusing. Credential folders such as `~/.ssh` stay protected.
- The workspace menu has a solid background, so the shell and run list behind it no longer shows through.

### Native terminal (beta)
- Canopy now includes Canopy Terminal, a native terminal window that runs separately from the Canopy window. Open one from **Tabs → New Native Terminal Window (beta)** or from the New… launcher. It starts in the project's folder.
- It scrolls through history, selects by word (double click) and line (triple click), copies, pastes safely, and finds text (Cmd-F; Ctrl-Shift-F on Windows and Linux). It draws underline styles and opens hyperlinks you Cmd-click (Ctrl-click elsewhere).
- With persistent terminals on, right-click a terminal tab and choose **Open in Native Window** to move that terminal into a native window. The tab then shows "Open in native window" with **Take back**. Closing the window leaves the terminal running, and you can take it back from the tab.
- Optional settings live in a file, not in Canopy's Settings: font family and size, line height, padding, blinking, and a light or dark theme or your own colours. See `config.example.toml` in the app's source, or run `canopy-term-app --print-config` to see what is in effect.
- It is not included in the Windows build yet. If the app was built without it, the menu entries are not shown.

### Limitations
- Persistent terminals are on by default on Mac and Linux and are untested on a real signed build. Updating the app while terminals are running, the macOS signing of the terminal helper, and macOS folder-permission prompts naming the helper instead of Canopy are all first exercised by this release.
- Persistent terminals do not work on Windows. On Linux, the AppImage has not been tried.
- Terminals started by tasks that run in the background are not reconnected.
- Tailscale Connect has not been tried across two real machines. It only reaches terminals on a machine whose Canopy is open, and a machine you allow has full control. Machines shared from another Tailscale network are not listed.
- Canopy Terminal is a beta. It has no Settings page for its options (only the config file), and its macOS signing, the windows it opens from the menu, and Open in Native Window are first exercised on a real signed build by this release.
- Previews that use Chrome need Node installed; otherwise they use the built-in view.
- Download refuses folders of more than 20,000 files, so large folders such as node_modules will not download. It is in the right-click menu only.
- The drafted commit message and description are sent without being shown. Only the title is.
- Preview pictures can be up to 12 seconds old.
- Several of these changes have only been checked by tests, not in a built app.
