Canopy 0.5.2 makes the brain run on the agent CLI you chose, signed in to the account you chose, and stops the Brain settings from showing another CLI's result.

### The brain uses the CLI you picked
If Canopy couldn't find your chosen CLI on this computer, Canopy's smart features, such as commit messages, session names and reviews, quietly ran on whichever other agent CLI was installed. Settings still named the one you chose. For example, you could pick Claude Code and have Codex answer, on Codex's own default model. Now the brain is the CLI you chose, or nothing. If it isn't installed here, **Settings → Brain** says so and offers **Use** for one that is, so a switch is always your decision. Canopy checks once more before saying a CLI is missing, so a CLI you just installed is picked up.

### The brain uses your active account
The brain now runs on the account selected in **Settings → Accounts**, like your agent sessions do. Before, it always used the CLI's default sign-in and settings, which could be a different plan and model, such as a model your ChatGPT sign-in doesn't allow. The brain always runs on your own computer, so in a cloud workspace whose account exists only on the workspace, it keeps using your computer's default sign-in.

### Brain settings show the right status
If you switched brains while a check was still running, the old CLI's answer could appear under the new one's name, for example "Claude Code · Codex CLI did not answer". Answers from a CLI that is no longer your brain are now ignored, and switching checks the new one. The panel never shows one CLI's error under another's name.

When you switch to a different CLI, its main and background models go back to that CLI's defaults, because model names like `haiku` only work with the CLI they belong to.
